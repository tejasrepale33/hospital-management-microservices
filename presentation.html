Problem Statement & Objectives

Engineering Goals & System Highlights

Challenges in Monoliths
  • Single Point of Failure: Outages in scheduling halt patient intakes.
  • Slow Symptom Triage: Delays in directing critical patients to specialists.
  • Heavy Database Strain: Constant doctor queries saturate disk I/O.
  • Security Gaps: Inconsistent authentication across internal APIs.
Engineered Solutions
  • Decoupled Microservices: Independent Auth, Patient, and Doctor domains.
  • Spring AI Symptom Triage: Automated severity scoring and department mapping.
  • Redis In-Memory Cache: Sub-2ms doctor catalog lookups.
  • Central Gateway Filter: Zero-trust Bearer token validation at entry.
Key Deliverables
  • High Availability: Eureka client-side load balancing.
  • Dual PostgreSQL DBs: patient_db and doctor_db schemas.
  • Eclipse & STS Native: Maven multi-module ready for 1-click import.
  • Full Containerization: One-command launch with docker-compose.

Discovery & Elastic Scaling

Netflix Eureka & Load Balancing

Netflix Eureka Server (Port 8761)
  • Dynamic Service Registration: Microservices register themselves upon boot with their logical names (e.g., PATIENT-SERVICE, DOCTOR-SERVICE).
  • Continuous Heartbeat Healthchecks: Sent every 30 seconds; unviable instances are purged automatically.
  • Dashboard Monitoring: Live graphical console at http://localhost:8761 displaying instance IPs, ports, and status.
  • No Hardcoded Hosts: Decouples internal container networking from host machines.
Spring Cloud LoadBalancer
  • Gateway Load Balancing: Route URIs use the lb:// protocol (e.g., lb://doctor-service) to distribute incoming requests across replicas.
  • Inter-Service Communication: Patient Service utilizes a @LoadBalanced RestTemplate to invoke http://doctor-service/api/doctors/department/{dept}.
  • Zero Edge Latency: Traffic flows directly between microservices within the internal network.
  • Fault Tolerant: Retries alternate instances when an endpoint fails.
Edge Security & Routing

Spring Cloud API Gateway & Filter

Gateway Routes & Whitelisting
# Gateway Route Table
/api/auth/**      -> lb://auth-service     (PUBLIC)
/api/patients/**  -> lb://patient-service  (PROTECTED)
/api/doctors/**   -> lb://doctor-service   (PROTECTED)

# Whitelisted Endpoints (RouteValidator)
• /api/auth/register
• /api/auth/login
• /api/auth/validate
• /actuator/**
JwtAuthenticationFilter Logic
  • Path Inspection: If requested path is in the whitelist, skips validation and allows request through.
  • Token Extraction: Extracts Bearer <token> from the Authorization header. Returns 401 if missing.
  • Cryptographic Verification: Validates HMAC-SHA256 signature and expiration timestamp with the shared 256-bit secret.
  • Header Mutation: Injects X-Auth-Username and X-Auth-Role into request headers for downstream microservices.
Identity & Access Management

Spring Security 6 & JJWT Tokens

Token Generation & Claims
// JWT Structure (io.jsonwebtoken:jjwt-api:0.12.5)
Header:    {"alg": "HS256", "typ": "JWT"}
Payload:   {
  "sub": "patient_john",
  "role": "ROLE_PATIENT",
  "iat": 1773054000,
  "exp": 1773140400 // 24 Hours TTL
}
Signature: HMACSHA256(Base64URL(Header) + "." + 
                      Base64URL(Payload), secretKey)
Security Capabilities
  • BCrypt Salting & Hashing: Passwords stored as one-way BCrypt hashes; plaintext is never retained.
  • Role-Based Access Control (RBAC): Separates patient operations from clinician schedule modifications (ROLE_PATIENT, ROLE_DOCTOR, ROLE_ADMIN).
  • Stateless Architecture: Zero server-side session locks; microservices scale horizontally without session replication.
  • Token Validation Endpoint: Dedicated /api/auth/validate?token=... for microservice verification.
Artificial Intelligence

Spring AI Symptom Triage Engine

Clinical Diagnostic Workflow
  • Natural Language Symptoms: Accepts descriptions like "severe chest pain radiating to left arm" or "skin rash and itching".
  • Urgency Stratification: Maps conditions into 4 clinical tiers: EMERGENCY, HIGH, MODERATE, LOW.
  • Automated Department Referral: Directs patients to Cardiology, Neurology, Dermatology, Orthopedics, or General Medicine.
  • Care & Diagnostic Advice: Prescribes immediate precautions (e.g. R.I.C.E protocol) and suggested diagnostic tests (ECG, Troponin, MRI).
Live Doctor Matching & Fallback
  • Automated Doctor Lookup: Triage service triggers inter-service query to doctor-service and returns top-rated matching doctors with open booking slots!
  • Zero-Failure Offline Engine: Works with Spring AI OpenAI / Ollama if keys are present, and seamlessly activates the built-in clinical rule base offline when keys are omitted!
  • Structured JSON Response: Returns diagnostic hypothesis, urgency tier, precautions, and suggested specialist profiles in a single call.
Caching & Performance

Distributed Redis Caching Strategy

Cache-Aside Architecture
  • Spring Cache Abstraction: @EnableCaching with @Cacheable(value = "doctors") intercepts queries.
  • Performance Gain: Database queries take ~50-80ms; Redis in-memory hits take < 2ms (97% latency reduction).
  • TTL Expiration: Keys expire automatically in 15 minutes to guarantee fresh information.
  • JSON Serializer: GenericJackson2JsonRedisSerializer ensures cache values are stored as readable JSON strings.
Eviction & Resilient Error Handling
  • Automatic Invalidation: @CacheEvict(allEntries = true) automatically invalidates stale entries whenever doctor details or availability change.
  • Resilient CacheErrorHandler: Custom error handler catches Redis connectivity timeouts. If Redis is offline, queries fall back seamlessly to PostgreSQL without crashing!
  • Namespace Isolation: Distinct prefixes (doctors::, patients::) prevent cross-service key collisions.
PostgreSQL Dual-Database

Database Schemas: patient_db & doctor_db

patient_db (Port 5432)
TABLE patients (
  id BIGSERIAL PRIMARY KEY,
  first_name VARCHAR(255) NOT NULL,
  last_name VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  phone VARCHAR(50), age INT, gender VARCHAR(20),
  blood_group VARCHAR(10), address TEXT,
  emergency_contact VARCHAR(50),
  medical_history TEXT
);

TABLE appointments (
  id BIGSERIAL PRIMARY KEY,
  patient_id BIGINT REFERENCES patients(id),
  doctor_id BIGINT, doctor_name VARCHAR(255),
  department VARCHAR(100), appointment_date DATE,
  time_slot VARCHAR(50), status VARCHAR(50),
  symptoms TEXT, notes TEXT
);
doctor_db (Port 5432)
TABLE doctors (
  id BIGSERIAL PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  department VARCHAR(100) NOT NULL,
  specialization VARCHAR(255) NOT NULL,
  email VARCHAR(255) UNIQUE NOT NULL,
  phone VARCHAR(50), consultation_fee FLOAT8,
  rating FLOAT8, experience_years INT,
  is_available BOOLEAN DEFAULT TRUE
);

TABLE availability_slots (
  id BIGSERIAL PRIMARY KEY,
  doctor_id BIGINT REFERENCES doctors(id),
  day_of_week VARCHAR(20) NOT NULL,
  start_time VARCHAR(20), end_time VARCHAR(20),
  is_booked BOOLEAN DEFAULT FALSE
);
UML Working Activity Diagram

Patient Triage & Appointment Booking Flow

1. Authenticate
Patient registers or logs in via /api/auth/login and acquires signed JWT Bearer token.
2. Submit Symptoms
Submits natural symptoms to /api/patients/ai/symptom-triage with duration and history.
3. AI Evaluation
Spring AI scores urgency (Emergency/High/Mod), deduces department, precautions, and lab tests.
4. Doctor Referral
Inter-service call to Doctor Service returns matching clinicians with available open slots.
5. Select Slot
Patient chooses preferred doctor and booking slot for consultation.
6. Book Appointment
Submits booking request to /api/patients/{id}/appointments with symptoms and notes.
7. Redis & DB Sync
Appointment written to patient_db, slot locked in doctor_db, cache refreshed.
8. Confirmed
Returns appointment confirmation ID and instructions to the patient.
UML Working Activity Diagram

Doctor Onboarding & Schedule Management

1. Onboard Doctor
Admin registers credentials with ROLE_DOCTOR in auth-service.
2. Ingest Profile
Doctor record saved in doctor_db with specialty, department, and consultation fees.
3. Configure Slots
Doctor specifies consultation slots (Day of week, Start & End times).
4. Redis Invalidation
@CacheEvict purges outdated doctor lists so new slots reflect instantly.
5. Patient Search
Patients browse doctors by department or specialization through API Gateway.
6. Slot Lock
Booking toggles is_booked = true to prevent double booking.
7. Consultation
Doctor conducts medical consultation and records clinical notes.
8. Completed
Appointment marked COMPLETED in PostgreSQL database.

DevOps & Orchestration

Docker Multi-Container Orchestration

Container Architecture
  • postgres:15-alpine: Boots up PostgreSQL with auto-initialization script for patient_db and doctor_db.
  • redis:7-alpine: Distributed cache container on port 6379 with automatic healthcheck.
  • service-registry: Eureka Server container on port 8761.
  • api-gateway: Edge reverse-proxy container on port 8080.
  • auth, patient, doctor services: Alpine JRE microservice containers connected via bridge network hospital-net.
Docker CLI Execution
# 1. Build and start all 7 containers in background
docker-compose up --build -d

# 2. Verify all services are healthy and running
docker-compose ps

# 3. Stream real-time logs from patient service
docker-compose logs -f patient-service

# 4. Scale Patient Service to handle high loads
docker-compose up --scale patient-service=3 -d

# 5. Stop and clean up containers
docker-compose down -v
Developer Setup

Eclipse IDE & Spring Tool Suite Guide

1. Import Project
  • Open Eclipse / STS.
  • Go to File → Import...
  • Select Maven → Existing Maven Projects.
  • Browse to project root folder and click Finish.
2. Launch Order
  • 1st: ServiceRegistryApplication (8761)
  • 2nd: AuthServiceApplication (8081)
  • 3rd: DoctorServiceApplication (8083)
  • 4th: PatientServiceApplication (8082)
  • 5th: ApiGatewayApplication (8080)
3. Run As Spring Boot
  • Right-click each Application class → Run As → Spring Boot App (or Java Application).
  • Open http://localhost:8761 to see all 4 services registered in Eureka!
